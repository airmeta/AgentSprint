# 项目材料与提案管理需求细节

## 1. 总体说明

项目材料是项目管理的基础资料库，用来保存需求调研文档、会议纪要、客户资料、截图、验收材料、历史方案和其他与项目有关的文件。第一版不引入对象存储，所有上传文件先保存到 API 运行目录下，并按 `projectId` 隔离。

后续提案管理会基于项目材料选择若干文件，与 AI 对话生成提案信息。提案确认后可以转为需求，进入现有需求评审、任务拆解、开发、测试和缺陷闭环。

本需求的核心目标：

- 在项目管理中增加项目材料上传和管理能力。
- 材料按项目隔离存储，支持类似文件管理的目录、列表、上传、下载、重命名、删除和检索。
- 为后续提案管理预留材料选择、文本抽取、AI 生成和提案转需求的数据关系。
- 不绕过现有需求生命周期，提案转需求后仍从草稿或待评审开始。

## 2. 业务边界

### 2.1 第一版范围

第一版只做平台内材料管理：

- 项目管理详情中增加 `项目材料` 入口。
- 支持按项目上传文件。
- 支持文件夹或逻辑目录。
- 支持文件列表、筛选、下载、预览信息、重命名、移动和删除。
- 文件实体落库，文件内容落在 API 运行目录。
- 删除先做软删除，物理文件可保留，后续由清理任务处理。
- 文件大小、扩展名和 MIME 类型做基础校验。
- 上传、删除、下载记录审计事件。

第一版不强制实现：

- 对象存储。
- 文件在线编辑。
- 协同批注。
- 全文检索引擎。
- 大文件分片上传。
- 文档 OCR。
- Office/PDF 完整在线预览。

### 2.2 第二版范围

第二版围绕 AI 提案准备能力：

- 对可解析文件抽取文本内容。
- 生成文件摘要。
- 支持选择项目材料进入提案生成上下文。
- 支持保存 AI 对话过程、提案草稿和来源材料。
- 支持提案版本。

### 2.3 第三版范围

第三版形成提案到需求的闭环：

- 提案提交评审或确认。
- 提案一键转需求。
- 新需求保留 `sourceProposalId` 和来源材料列表。
- 转出的需求继续走现有需求评审、任务拆解、开发、测试和缺陷流程。

## 3. 文件存储需求

### REQ-MATERIAL-001：按项目隔离保存上传文件

目标：

上传文件先保存到 API 运行目录，并按 `projectId` 分目录隔离。

建议默认目录：

```text
{ApiRunDirectory}/project-materials/{projectId}/
```

其中 `ApiRunDirectory` 第一版可使用 .NET API 的 `AppContext.BaseDirectory`。后续如果部署形态要求更稳定的数据目录，可以通过配置项迁移到独立挂载目录。

建议物理目录结构：

```text
project-materials/
  {projectId}/
    files/
      2026/
        06/
          {materialId}{extension}
    extracted/
      {materialId}.txt
    thumbnails/
      {materialId}.png
```

处理逻辑：

- 原始文件名只保存到数据库，不直接作为物理文件名。
- 物理文件名使用 `materialId + extension`，避免重名、路径穿越和编码问题。
- 逻辑目录使用数据库字段表达，不能直接信任用户传入路径写磁盘。
- 所有物理路径必须归一化并校验仍在项目材料根目录下。

验收标准：

- 同名文件可以重复上传，不覆盖旧文件。
- 不同项目的文件不能落到同一目录。
- 文件名包含中文、空格、特殊字符时仍可上传、下载和展示。
- 构造 `../` 的文件名不能写出项目材料目录。

### REQ-MATERIAL-002：上传文件并保存元数据

目标：

用户在项目材料页面上传文件后，平台保存文件和元数据。

上传参数：

- `projectId`
- `parentId`
- `category`
- `tags`
- `description`
- `file`

元数据字段建议：

| 字段 | 说明 |
| --- | --- |
| `Id` | 材料 ID。 |
| `ProjectId` | 所属项目。 |
| `ParentId` | 所属文件夹，为空表示根目录。 |
| `ItemType` | `file` 或 `folder`。 |
| `Name` | 展示名称。 |
| `OriginalFileName` | 上传原文件名。 |
| `Extension` | 扩展名。 |
| `ContentType` | MIME 类型。 |
| `SizeBytes` | 文件大小。 |
| `StorageRoot` | 存储根类型，第一版为 `api_run_directory`。 |
| `RelativePath` | API 运行目录下的相对路径。 |
| `Sha256` | 文件哈希。 |
| `Category` | 材料分类。 |
| `TagsJson` | 标签。 |
| `Description` | 说明。 |
| `ExtractStatus` | 文本抽取状态。 |
| `Summary` | 文件摘要，后续 AI 填充。 |
| `UploadedBy` | 上传人。 |
| `CreatedAt` | 创建时间。 |
| `UpdatedAt` | 更新时间。 |
| `DeletedAt` | 软删除时间。 |

验收标准：

- 上传成功后列表能看到文件名、大小、类型、上传人和上传时间。
- 服务端能校验项目存在。
- 服务端能校验当前用户具备项目材料上传权限。
- 上传失败不会留下不可引用的数据库记录。

### REQ-MATERIAL-003：文件夹和目录管理

目标：

材料页提供类似文件管理的目录体验。

能力：

- 新建文件夹。
- 进入文件夹。
- 面包屑返回上级。
- 重命名文件或文件夹。
- 移动文件或文件夹。
- 删除文件或文件夹。

处理逻辑：

- 文件夹只落库，不创建实际物理目录也可以。
- 删除文件夹时如果包含未删除子项，第一版可以拒绝删除。
- 移动时不能把文件夹移动到自身或子孙目录下。
- 同一父目录下不允许同名文件夹。
- 同一父目录下允许同名文件，但列表需要通过上传时间或扩展信息区分。

验收标准：

- 能在项目下创建多层目录。
- 面包屑路径和当前目录一致。
- 非法移动被服务端拒绝。
- 删除后默认列表不展示软删除项。

### REQ-MATERIAL-004：材料列表与检索

目标：

用户能按项目、目录、类型、分类、标签和关键词查找材料。

筛选项：

- 项目。
- 当前目录。
- 文件类型。
- 分类。
- 标签。
- 上传人。
- 创建时间。
- 关键词。

列表字段：

- 序号。
- 名称。
- 类型。
- 大小。
- 分类。
- 标签。
- 上传人。
- 上传时间。
- 抽取状态。
- 操作。

操作：

- 进入文件夹。
- 下载。
- 详情。
- 重命名。
- 移动。
- 删除。

验收标准：

- 列表支持分页。
- 查询和重置按钮可用。
- 当前目录变化后分页回到第一页。
- 删除、重命名、移动后列表刷新。

### REQ-MATERIAL-005：下载和访问控制

目标：

项目成员只能下载自己有权限访问的项目材料。

处理逻辑：

- 下载接口通过 `materialId` 查询数据库，再解析物理文件路径。
- 下载前校验项目权限。
- 只允许下载 `ItemType=file` 且未删除的材料。
- 下载响应使用原始文件名。
- 不直接暴露物理路径。

验收标准：

- 非项目成员不能下载材料。
- 被软删除的材料不能下载。
- 文件不存在时返回明确错误。

### REQ-MATERIAL-006：文本抽取预留

目标：

为后续 AI 提案生成准备材料文本上下文。

第一版处理：

- `.md`、`.txt` 可以直接读取文本并保存抽取结果。
- 其他类型先标记为 `pending` 或 `unsupported`。
- 文本抽取结果保存到 `extracted/{materialId}.txt` 或数据库文本字段。

后续处理：

- `.docx` 使用 OpenXML 或文档解析库抽取。
- `.pdf` 使用 PDF 解析库抽取。
- `.xlsx` 抽取工作表结构和主要文本。
- 图片类文件接 OCR 后再进入 AI 上下文。

验收标准：

- 上传 `.md` 或 `.txt` 后能得到 `ExtractStatus=completed`。
- 不支持的文件不会阻塞上传。
- 提案生成只能选择可用文本或允许用户确认使用文件摘要。

## 4. 提案管理需求

### REQ-PROPOSAL-001：从项目材料创建提案草稿

目标：

产品经理或项目经理选择项目材料后，创建提案草稿。

输入：

- `projectId`
- `title`
- `materialIds`
- `instruction`

处理逻辑：

- 校验所有材料属于同一项目。
- 校验材料未删除且当前用户可读。
- 保存提案草稿。
- 保存提案与材料的关联关系。
- 保存创建来源为 `project_materials`。

验收标准：

- 可以从材料列表勾选文件并创建提案。
- 跨项目材料不能混选。
- 提案详情能看到来源材料列表。

### REQ-PROPOSAL-002：AI 对话生成提案内容

目标：

用户基于选中的项目材料与 AI 对话，生成提案信息。

提案内容建议：

- 背景。
- 目标。
- 范围。
- 关键问题。
- 解决方案。
- 业务价值。
- 验收口径。
- 风险和依赖。
- 建议拆分的需求列表。

处理逻辑：

- 组装材料摘要和抽取文本。
- 控制上下文长度，优先使用摘要和用户选定片段。
- 保存 AI 请求、回复、材料快照和用户最终确认内容。
- AI 生成结果不直接进入需求，必须先保存为提案草稿。

验收标准：

- AI 对话结果可保存为提案正文。
- 提案正文可编辑。
- 提案保留生成时使用的材料 ID 和材料版本信息。

### REQ-PROPOSAL-003：提案转需求

目标：

确认后的提案可以转为一个或多个需求。

处理逻辑：

- 用户从提案中选择转需求。
- 平台生成 `SprintRequirement`。
- 新需求保留 `SourceProposalId`。
- 新需求保留来源材料 ID 列表。
- 新需求状态默认为 `draft`，也可按配置进入 `pending_review`。
- 转换后仍需要按现有流程评审、拆解、开发、测试和验收。

验收标准：

- 提案转需求后，需求详情能看到来源提案和来源材料。
- 需求不能绕过评审直接进入开发。
- 一个提案可以转出多条需求。

## 6. 审计需求

材料审计事件：

- `project_material_uploaded`
- `project_material_folder_created`
- `project_material_renamed`
- `project_material_moved`
- `project_material_deleted`
- `project_material_downloaded`
- `project_material_extract_completed`
- `project_material_extract_failed`

提案审计事件：

- `proposal_created_from_materials`
- `proposal_ai_generation_started`
- `proposal_ai_generation_completed`
- `proposal_updated`
- `proposal_converted_to_requirement`

审计字段：

- 操作人。
- 项目 ID。
- 材料 ID 或提案 ID。
- 操作类型。
- 脱敏后的请求参数。
- 结果。
- 时间。

## 7. 异常和安全需求

### 7.1 文件安全

- 禁止使用用户原始文件名拼接物理路径。
- 禁止下载接口接受任意路径。
- 限制单文件大小。
- 限制总容量或给出容量统计。
- 限制可上传扩展名。
- 保存文件哈希，便于重复文件识别。
- 不在日志中打印本地完整物理路径以外的敏感信息。

### 7.2 运行目录风险

第一版放在 API 运行目录是为了快速落地，但需要明确风险：

- 容器重建或发布覆盖时可能丢失文件。
- 多实例部署时本地文件不共享。
- 备份需要覆盖 API 运行目录下的材料目录。

因此第一版部署必须确认：

- Docker 或服务器部署时将 `project-materials` 目录挂载到持久化卷。
- 发布脚本不能清空材料目录。
- 后续迁移对象存储时保留 `StorageRoot` 和 `RelativePath` 的抽象。

## 8. 最小 MVP 验收闭环

MVP 闭环：

```text
项目管理
  -> 打开项目详情
  -> 进入项目材料
  -> 新建文件夹
  -> 上传材料
  -> 列表展示材料
  -> 下载材料
  -> 重命名材料
  -> 删除材料
  -> 审计事件可查
```

MVP 验收点：

- 文件实际保存到 `{ApiRunDirectory}/project-materials/{projectId}`。
- 数据库有材料元数据。
- 管理端材料页有查询、重置、上传、刷新、列表、分页和行操作。
- 非项目成员不能访问材料。
- 删除后下载接口拒绝访问。
- 不影响现有项目、需求、任务、测试和缺陷流程。
