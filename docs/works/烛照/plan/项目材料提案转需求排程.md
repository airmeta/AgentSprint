# 项目材料提案转需求排程

## 1. 目标

本排程把项目材料、提案管理、提案转需求拆成可连续交付的阶段。第一阶段先完成项目材料文件管理，后续再接 AI 提案生成和提案转需求，避免一次性把文件系统、AI 对话和需求流转混在一起。

## 2. 阶段划分

### M1：项目材料后端基础

目标：

建立按项目隔离的材料存储、元数据和基础接口。

交付项：

- 新增项目材料配置项。
- 新增 `SprintProjectMaterial` 实体和数据库初始化 SQL。
- 新增 `SprintProjectMaterialEvent` 审计实体和 SQL。
- 新增材料服务 `IProjectMaterialService`。
- 新增材料 Controller。
- 实现列表、创建文件夹、上传、详情、下载、重命名、移动、删除。
- 文件保存到 `{ApiRunDirectory}/project-materials/{projectId}`。
- 上传使用服务端生成文件名。
- 下载不暴露物理路径。

验收点：

- 上传文件后数据库有记录，磁盘有文件。
- 同名文件不会覆盖。
- 不同项目文件物理隔离。
- 非项目成员不能访问。
- 路径穿越文件名被拒绝。
- 删除后不能下载。

建议测试：

```text
dotnet test src/api/AgentSprint.slnx --no-restore --filter ProjectMaterial
```

### M2：项目材料管理端页面

目标：

在项目管理中做出类似文件管理的项目材料页面。

交付项：

- 项目详情抽屉增加 `项目材料` 入口。
- 新增或抽取项目材料列表组件。
- 支持面包屑目录。
- 支持查询、重置、上传、新建文件夹、刷新。
- 表格展示文件夹和文件。
- 行操作支持打开、下载、详情、重命名、移动、删除。
- 上传表单放在 Dialog 或 Drawer。
- 列表支持分页。

验收点：

- 从项目管理能进入项目材料。
- 上传、下载、重命名、删除能完成完整闭环。
- 查询和重置按钮可点击且状态正确。
- 表格有序号列和操作列。
- 所有行操作有图标和文字。
- 切换项目时当前目录和分页重置。

建议验证：

```text
corepack pnpm -F @vben/web-tdesign run typecheck
```

### M3：材料文本抽取和摘要预留

目标：

为 AI 提案生成准备材料文本上下文。

交付项：

- 新增抽取状态字段和抽取结果路径。
- 上传 `.md`、`.txt` 时同步抽取文本。
- 其他扩展名标记为 `pending` 或 `unsupported`。
- 材料详情展示抽取状态。
- 预留手动重新抽取接口。
- 后续可接 PDF、DOCX、XLSX 解析。

验收点：

- `.md` 和 `.txt` 上传后抽取状态为 `completed`。
- 不支持文件不影响上传。
- 材料详情能看到摘要或抽取状态。

### M4：提案管理后端基础

目标：

新增提案数据模型和提案基础接口，先不接 AI。

交付项：

- 新增 `SprintProposal`。
- 新增 `SprintProposalMaterial`。
- 新增 `SprintProposalConversation`。
- 新增 `SprintProposalRequirement`。
- 新增 `IProposalService`。
- 新增提案列表、创建、详情、编辑、确认、作废接口。
- 创建提案时允许绑定项目材料。
- 校验材料必须属于同一项目。

验收点：

- 能从指定项目创建提案。
- 提案能绑定多个项目材料。
- 跨项目材料不能绑定到同一提案。
- 提案详情能返回来源材料。

### M5：提案管理端页面

目标：

新增提案管理入口，支持查看、编辑和从材料创建提案。

交付项：

- 新增 `敏捷研发 / 提案管理` 菜单。
- 提案管理页面使用项目上下文列表布局。
- 支持按项目、状态、关键词、创建人筛选。
- 支持新增提案。
- 支持从项目材料选择文件创建提案。
- 提案详情抽屉展示基础信息、来源材料、正文和转换记录。

验收点：

- 提案列表能按项目过滤。
- 从材料创建提案后，来源材料可见。
- 提案正文可编辑保存。
- 页面符合管理端列表规范。

### M6：AI 生成提案

目标：

选择项目材料后，通过 AI 对话生成提案正文。

交付项：

- 新增提案生成接口。
- 组装项目、材料摘要和抽取文本上下文。
- 保存 AI prompt 快照和结果快照。
- 保存提案对话记录。
- 管理端支持 `AI 生成` 和继续补充指令。
- 生成结果进入提案正文草稿。

验收点：

- 选择材料后能生成提案正文。
- 生成过程保留来源材料和 prompt 快照。
- 用户能编辑 AI 生成结果。
- AI 生成失败不会破坏提案草稿。

### M7：提案转需求

目标：

确认后的提案可以转为一个或多个需求，并接入现有需求闭环。

交付项：

- 新增提案转需求接口。
- `SprintRequirement` 补充 `SourceProposalId` 和 `SourceMaterialIdsJson`。
- 提案转需求时写入 `SprintProposalRequirement`。
- 管理端提案详情增加 `转需求` 操作。
- 支持单条或多条需求转换。
- 可选提交评审，但必须复用现有评审逻辑。

验收点：

- 提案能转出需求。
- 新需求详情能看到来源提案和来源材料。
- 新需求默认不绕过评审。
- 一个提案可以转多条需求。
- 已转需求的提案能看到转换记录。

### M8：部署和数据持久化加固

目标：

确保 API 运行目录下的材料在部署和容器重启后不丢失。

交付项：

- Docker compose 增加 `project-materials` 持久化挂载。
- 部署文档说明材料目录。
- 发布脚本确认不清理材料目录。
- 增加材料目录健康检查或启动提示。
- 增加容量统计。

验收点：

- 容器重启后材料仍可下载。
- API 重发版后材料不丢失。
- 部署文档说明挂载目录和备份策略。

## 3. 推荐实施顺序

1. M1 后端材料基础。
2. M2 管理端材料页面。
3. M8 的持久化挂载先做最小版本，避免测试环境文件丢失。
4. M3 文本抽取。
5. M4 提案后端基础。
6. M5 提案页面。
7. M6 AI 生成提案。
8. M7 提案转需求。

## 4. 第一轮最小交付

如果只做最小可用版本，建议第一轮只完成：

- M1：项目材料后端基础。
- M2：项目材料管理端页面。
- M8：部署挂载说明。

第一轮不做 AI 生成，也不做提案转需求，只保证项目材料可以可靠上传、管理和下载。

## 5. 风险和处理

### 5.1 API 运行目录不稳定

风险：

发布覆盖或容器重建可能导致文件丢失。

处理：

- 第一版必须加部署挂载说明。
- 数据模型保留 `StorageRoot`，便于后续迁移。

### 5.2 文件安全

风险：

上传文件名和下载参数可能触发路径穿越。

处理：

- 服务端生成物理文件名。
- 任何下载都从数据库查 `RelativePath`。
- 写入和读取前做根目录校验。

### 5.3 AI 上下文过长

风险：

选择大量材料后 prompt 超长，生成质量下降。

处理：

- 先用材料摘要。
- 大文件切片。
- 用户明确选择进入上下文的材料。
- 保存生成快照，便于复盘。

### 5.4 提案绕过需求流程

风险：

提案转需求直接进入开发会破坏现有闭环。

处理：

- 转出的需求默认 `draft`。
- 可选提交评审也必须走现有评审服务。
- 需求保留来源提案和材料，便于审计。
