# 数字员工优化方案

## 目标

本方案用于优化 AgentSprint 数字员工从平台创建、生成安装配置、人工部署、首次激活、任务接取、维护停用到软删除的完整生命周期。

核心目标：

- 平台只生成安装材料，不自动 SSH、不自动部署、不自动执行 Docker 命令。
- 新建数字员工默认未激活，必须由真实 Worker 容器首次上线并完成启动探针后才允许接任务。
- 任务拆解、任务指派只能选择可接任务的数字员工。
- 删除必须软删除，并受到任务完成状态约束。
- Agent Token 在未删除数字员工之间必须唯一绑定。
- 启动环境能力通过平台配置的探针命令检测，并在审计页展示。

## 生命周期状态

数字员工管理状态使用以下枚举：

| 状态 | 含义 | 是否允许接新任务 |
| --- | --- | --- |
| inactive | 未激活。平台已创建主档，但真实容器尚未完成启动。 | 否 |
| starting | 正在启动。Worker 已拉配置、注册或心跳，但启动探针尚未全部通过。 | 否 |
| idle | 待命。已激活且可接新任务。 | 是 |
| working | 正在工作。已有任务、命令或运行记录执行中。 | 否 |
| maintenance | 维护中。禁止接取新任务，允许已有任务跑完。 | 否 |
| disabled | 停用。只允许从维护状态且所有任务完成后进入。 | 否 |
| deleted | 已删除。通过软删除表达，不作为普通业务状态流转。 | 否 |

状态流转：

```text
创建 -> inactive
生成安装配置 -> inactive
Worker 拉配置/注册/首次心跳 -> starting
启动探针全部通过 -> idle
接到任务或 run 开始 -> working
任务全部结束 -> idle
人工维护 -> maintenance
maintenance 且所有任务完成 -> disabled
disabled -> deleted
```

## 安装配置生成

数字员工列表操作列保留：

- 安装
- 删除

点击“安装”后，平台生成并展示组装后的 `docker-compose.yml`。用户可以复制或下载，然后自行登录服务器执行部署命令。

平台不自动处理：

- SSH 连接
- 文件上传
- `docker compose build`
- `docker compose up -d`
- 远程环境检查

### 明文输出选项

安装弹窗提供“明文输出”选项：

- 开启明文：生成一个完整 `docker-compose.yml`，Token 等环境变量直接组合进去。
- 关闭明文：拆分为 `docker-compose.yml` 和 `.env`，compose 中只保留环境变量引用。

关闭明文时示例：

```yaml
services:
  {{serviceName}}:
    environment:
      AgentSprint__ApiBaseUrl: "{{apiBaseUrl}}"
      AgentSprint__AgentToken: "${AGENTSPRINT_AGENT_TOKEN}"
      AgentSprint__WorkerDeployRenderId: "{{workerDeployRenderId}}"
```

`.env` 示例：

```dotenv
AGENTSPRINT_AGENT_TOKEN=your-agent-token
```

## 部署模板

新增数字员工部署模板，用于维护 compose 模板和运行环境扩展片段。

建议表名：

```text
digital_worker_deploy_template
```

关键字段：

| 字段 | 含义 |
| --- | --- |
| Id | 模板 ID |
| Code | 模板编码，例如 dotnet-default、java17、python311 |
| Name | 模板名称 |
| Description | 模板描述 |
| RuntimeProfile | 运行画像 |
| BackendTechCapabilities | 默认后端技术能力，例如 dotnet、dotnet,java |
| ComposeTemplate | docker-compose.yml 模板正文 |
| DockerfileExtension | 可选 Dockerfile 扩展片段 |
| Version | 模板版本 |
| Sort | 排序 |
| Status | 启用状态 |
| CreateTime / UpdateTime / IsDelete | 通用审计字段 |

模板不做复杂引擎，只支持 `{{placeholder}}` 占位符替换。

示例占位符：

```text
{{workerCode}}
{{workerName}}
{{serviceName}}
{{containerName}}
{{imageName}}
{{apiBaseUrl}}
{{agentToken}}
{{workspaceRoot}}
{{runsRoot}}
{{codexHome}}
{{runtimeProfile}}
{{workerDeployRenderId}}
```

Java 17 模板的 Dockerfile 扩展片段：

```dockerfile
RUN apt-get update \
    && apt-get install -y --no-install-recommends openjdk-17-jdk-headless \
    && apt-get clean \
    && rm -rf /var/lib/apt/lists/*
```

## 安装生成记录

每次点击“安装”生成配置时，必须先写入一条生成记录，再把记录主键渲染进 compose 环境变量。

建议表名：

```text
digital_worker_deploy_render
```

关键字段：

| 字段 | 含义 |
| --- | --- |
| Id | 本次生成记录 ID |
| WorkerId | 数字员工 ID |
| TemplateId | 部署模板 ID |
| TemplateVersion | 使用的模板版本 |
| RenderedCompose | 渲染后的 docker-compose.yml |
| RenderedEnv | 渲染后的 .env，可为空 |
| PlainSecretEnabled | 是否明文输出 |
| PlaceholderValuesJson | 占位符取值快照 |
| CreatedBy | 生成人 |
| CreateTime / IsDelete | 通用审计字段 |

写入容器的环境变量建议命名：

```yaml
AgentSprint__WorkerDeployRenderId: "{{workerDeployRenderId}}"
```

该字段表达“本容器来自哪次安装配置生成记录”，比 `worker_template_version_id` 更准确。

## 模板校验

模板保存和渲染时都需要做校验。

保存时校验：

- 必须包含平台地址占位符或固定配置。
- 必须包含 Agent Token 占位符或 env 引用。
- 必须包含独立挂载目录占位符。
- service name 和 container name 不能固定死为某一个员工。
- Dockerfile 扩展片段不得包含明显危险命令。

渲染后校验：

- 不允许残留未知 `{{placeholder}}`。
- 明文关闭时，Token 不允许出现在 `docker-compose.yml` 正文。
- `AgentSprint__WorkerDeployRenderId` 必须存在。
- `AgentSprint__ApiBaseUrl` 必须存在。
- `AgentSprint__AgentToken` 必须存在或引用 `.env`。

## 启动探针

数字员工启动后需要执行平台配置的启动探针命令，并将结果上报平台。

建议新增配置表：

```text
digital_worker_startup_probe_config
```

关键字段：

| 字段 | 含义 |
| --- | --- |
| Id | 探针配置 ID |
| Code | 探针编码 |
| Name | 探针名称 |
| Command | 检查命令 |
| ExpectedPattern | 期望输出，可为空 |
| Required | 是否必须通过 |
| Sort | 排序 |
| Status | 启用状态 |
| CreateTime / UpdateTime / IsDelete | 通用审计字段 |

示例命令：

```bash
dotnet --version
java -version
python3 --version
git --version
codex --version
```

Worker 启动流程：

1. 调用 `/worker-runtime/config` 拉取运行配置。
2. 拉取启动探针配置。
3. 执行探针命令。
4. 上报探针结果。
5. 平台判断必需探针全部通过后，将状态从 `starting` 切换为 `idle`。

探针结果需要在数字员工审计页展示：

- 探针名称
- 命令
- exit code
- stdout/stderr 摘要
- 是否通过
- 上报时间
- `WorkerDeployRenderId`

## 激活与运行时规则

运行时接口规则：

- `inactive` 允许拉取运行配置。
- `inactive` 允许注册会话和首次心跳。
- 首次有效心跳后切换为 `starting`。
- 必需启动探针全部通过后切换为 `idle`。
- `idle` 才允许接新任务。
- `working` 不允许接新任务。
- `maintenance` 允许已有任务继续完成，但不派发新任务。
- `disabled` 不允许拉配置、注册会话、心跳接命令。
- 软删除员工不允许拉配置、注册会话、心跳接命令。

## 任务派发与指派规则

拆解和任务指派只能选择：

```text
Status == idle
```

后端必须强制校验，不依赖前端筛选：

- 创建 Worker 命令时，目标数字员工必须是 `idle`。
- 心跳返回命令时，只有 `idle` 或当前已绑定执行中的 worker 可以收到对应命令。
- 任务开始执行时，数字员工自动切换为 `working`。
- 任务结束后，如果没有其他运行中任务，切回 `idle`。
- 如果数字员工处于 `maintenance`，任务结束后保持 `maintenance`，不再接新任务。

技术能力校验：

- 数字员工模板声明 `BackendTechCapabilities`。
- Worker 启动探针上报实际运行环境。
- 任务派发时，项目后端技术栈必须被数字员工能力覆盖。
- Java 项目不能派给只有 .NET 能力的数字员工。

## Token 绑定规则

同一个 `AgentTokenId` 不能同时绑定多个未删除数字员工。

允许：

- 已软删除员工释放 Token 后，新员工复用该 Token。
- 编辑员工自身时保留原 Token。

建议增加数据库级保护：

- 新增 `ActiveAgentTokenKey` 字段。
- 未删除时写入 `AgentTokenId`。
- 软删除时清空。
- 对 `ActiveAgentTokenKey` 建唯一索引。

这样可以避免并发创建时绕过应用层唯一校验。

## 停用与删除规则

停用规则：

- 只能从 `maintenance` 状态停用。
- 停用前必须确认所有任务、命令、run、lease 都已结束。
- 停用后状态为 `disabled`。

删除规则：

- 只能删除 `disabled` 状态的数字员工。
- 删除一定是软删除。
- 软删除后设置 `IsDelete = 1`。
- 软删除后清空 `ActiveAgentTokenKey`。
- 软删除后容器实例不能再拉配置、注册会话、心跳接命令。
- 历史 session、command、run、event、probe 结果保留用于审计。

删除前检查：

- 无 pending / acked / running 的 worker_command。
- 无 pending / running 的 worker_run。
- 无 active task lease。
- 绑定 AgentUserId 下无未完成开发任务。
- 绑定 AgentUserId 下无未完成 Bug。

拒绝删除时应返回阻塞明细，例如：

```text
不能删除：待执行命令 1 个，运行中 Run 1 个，未完成开发任务 2 个。
```

## 前端调整

数字员工列表：

- 展示管理状态。
- 展示运行状态。
- 展示运行画像。
- 展示后端能力。
- 展示最近心跳时间。

操作列：

- 未删除员工展示“安装”。
- 只有 `disabled` 员工展示“删除”。
- `idle / working / maintenance / disabled` 状态按规则展示状态操作。

安装弹窗：

- 展示 `docker-compose.yml`。
- 明文关闭时展示 `.env`。
- 支持复制。
- 支持下载。
- 显示生成记录 ID。
- 显示模板版本。

审计页：

- 展示启动探针结果。
- 展示 `WorkerDeployRenderId`。
- 展示容器启动环境摘要。

## 第一阶段交付范围

第一阶段只完成平台侧生命周期闭环，不做自动部署。

交付项：

1. 增加数字员工管理状态：`inactive`、`starting`、`idle`、`working`、`maintenance`、`disabled`。
2. 新建数字员工默认 `inactive`。
3. 新增部署模板表和默认模板。
4. 新增安装生成记录表。
5. 安装弹窗生成并展示 `docker-compose.yml` / `.env`。
6. compose 中写入 `AgentSprint__WorkerDeployRenderId`。
7. 新增启动探针配置和上报结果。
8. 必需探针通过后自动进入 `idle`。
9. 拆解和任务指派只允许选择 `idle` 数字员工。
10. 任务开始自动切 `working`，任务结束按规则切回 `idle` 或保持 `maintenance`。
11. 停用只允许维护中且所有工作结束的数字员工。
12. 删除只允许已停用员工，并且执行软删除。
13. Agent Token 对未删除数字员工唯一绑定。
