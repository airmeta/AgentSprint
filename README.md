# 烛照项目自动化协同平台
 简称烛照协同平台,面向 AI Agent / Codex 的敏捷需求接取、开发、测试发布平台。/Agile workflow platform for Codex-style coding agents.

## 自动化流程

 通过模板化提示词结合MCP工具,将原本的开发模式提升到完全自动化的方式
 
 ## 特点
  项目以传统项目施工角度出发,减少了一些在中小型团队中应用的复杂流转流程,与OpenSepc与OpenClaw的区别是该项目是基于团队化,项目化的角度来推动项目研发,整体流程可管控,可统计


 ## 流程

   ### 个人准备
   1. 一个Codex环境可以访问到的git仓库
   2. 手动将项目拉取到你的文件夹中
   3. 在Codex配置项目工作区
   4. 配置完全访问权限(可以不配置,但是遇到问题Codex将会需要你确认,无法全自动化)

   ### 项目准备
   1. 在烛照协同平台建立系统项目
   2. 根据项目信息建立对应的端,例如: 管理端,移动端,IOS等
   3. 为对应的端建立项目需求,并配置是否需要评审
   4. 需求评审(如果需求需要评审则联系评审人评审)
   5. 需求任务拆解(将需求拆解成一条条待办任务)
   6. 任务大厅任务分配(在任务拆解时可以指定人完成,也可以由系统自动指定)

   ### 开始工作

   #### 人工推进
   1. 登录烛照协同平台中的我的任务列表找到需要处理的任务
   <img width="2560" height="1389" alt="image" src="https://github.com/user-attachments/assets/ca441c79-1925-4827-b33b-004e6624cfbb" />
   
   2. 选中任务并点击任务推进
   
   3. 根据弹出的抽屉复制MCP服务器信息,粘贴给Codex,让Codex配置MCP服务器(仅仅在初次配置/烛照协同平台迁移到其他位置时执行)
   <img width="2560" height="1389" alt="image" src="https://github.com/user-attachments/assets/e44b45e5-4f0b-4a45-82c0-f2a392fd1279" />
   
   4. 复制任务推进提示词,键入Codex项目工作空间聊天框中即可
   <img width="2560" height="1541" alt="image" src="https://github.com/user-attachments/assets/2d4464f6-03c7-4053-bafb-0b11d11031aa" />

   5. Codex会根据MCP返回的任务上下文、需求信息、Skill规则和验证要求执行当前任务,完成后可通过平台回写任务状态并继续查看下一项工作

   #### 数字员工
   1. 在数字员工管理中维护数字员工档案,配置绑定的项目、端、Skill、Agent Token、工作区、运行目录和Codex运行参数
   2. 将任务或缺陷指派给对应数字员工,平台会通过受控端心跳和命令轮询下发执行命令
   3. 数字员工受控端会准备Git工作区,拉取指定仓库和分支,再调用Codex执行平台生成的任务提示词
   4. 执行过程中可以在平台查看命令审计、实时日志、运行结果和异常信息,必要时可以对历史命令进行重放
   5. 执行成功后,受控端会根据工作区变更提交并推送代码,再将任务或缺陷状态回写到协同平台

## 后续规划
   1. 持续打磨敏捷研发闭环,优化项目、需求、评审、任务大厅、我的任务、测试验证、缺陷管理等页面体验,补齐高频操作的稳定性和测试覆盖。
   2. 完善MCP协同能力,将会话注册、任务上下文、Skill包、下一工作项、心跳、事件记录等工具链进一步落库审计,并补充项目文档清单加载与执行过程追踪能力。
   3. 深化Skill配置管理,支持按项目、端、需求、数字员工等维度选择执行规范,逐步增加版本管理、导入导出、启停控制和基于任务上下文的按需加载。
   4. 完善数字员工受控端,围绕注册、心跳、命令轮询、命令审计、历史命令重放、实时日志、工作区准备、自动提交与推送等能力继续增强,让服务器侧Codex执行更可控、可追溯。
   5. 强化Git与运行环境管理,统一维护仓库、分支、Git账号、Agent Token、服务容器、端口映射、部署目录、Compose文件和部署脚本,降低项目接入和测试环境维护成本。
   6. 推进自动部署与流水线集成,在现有Docker Compose部署包基础上,逐步接入Harbor、Jenkins、对象存储、远程服务器发布、回滚和部署结果回写。
   7. 完善产品反馈与优化建议闭环,继续优化需求反馈、任务反馈、优化建议、多来源转需求和后续需求跟踪,让产品、测试和研发的反馈可以自然进入下一轮迭代。
   8. 增加项目级统计与运行监控,从项目进度、任务状态、测试环境、数字员工、命令日志、服务状态等维度提供统一视图。
   9. 建设AI治理与安全审计能力,统一管理模型供应商、令牌、活动自动化会话、权限边界、敏感信息保护和AI执行内容审计。
   10. 增加代码审查管理,支持按项目和端配置代码审查Skill,让AI结合需求、任务和项目规范审查研发成果并形成可追踪记录。

## 注意事项

   1.不建议在已有的项目中推动此平台,这可能会导致代码发生大规模重构/数据库重建等危险性操作, 在尝试此平台时,优先建议尝试新的项目或者微服务架构中的某个单独的服务
